Cloud Computing Explained: Servers, Storage, and Services

There is no "cloud"—it is simply someone else's computers, orchestrated through API-driven virtualization fabrics and billed by the second. Here is how modern multi-tenant cloud platforms operate.

By Julian Vance • Senior Systems Architect
September 02, 2026 • 16 min read

1. Deconstructing the Cloud Metaphor

Before the advent of cloud computing, deploying software meant purchasing physical rack servers, waiting four weeks for shipping, physically racking the hardware in a leased colocation facility, wiring redundant power distribution units, and configuring network switches.

Cloud computing transforms physical capital expenses into operational utility expenses. Instead of buying hardware, you make an authenticated API call (or Terraform command), and a virtual machine boots within 30 seconds.

2. Hypervisors & Multi-Tenancy

How do multiple competing companies run software on the identical physical server without interfering with one another? Through Type 1 Bare-Metal Hypervisors (such as Linux KVM or AWS Nitro).

The hypervisor runs directly on the server's bare silicon, partitioning the physical CPUs, RAM, and PCIe buses into isolated Virtual Machines (VMs). Hardware virtualization extensions (Intel VT-x, AMD-V) enforce memory isolation at the CPU hardware level.

3. The Three Storage Archetypes

Cloud platforms categorize storage into three distinct architectures:

  • Block Storage (e.g., AWS EBS): Virtual hard drives attached over high-speed networks. The operating system formats it with a native filesystem (ext4, XFS). Essential for databases.
  • Object Storage (e.g., AWS S3, Cloudflare R2): Highly distributed, infinitely scalable flat key-value storage. Files are accessed via HTTP REST APIs. Essential for images, backups, and static website hosting.
  • File Storage (e.g., NFS, AWS EFS): Managed shared filesystems concurrently mountable by hundreds of VMs.

4. The Compute Spectrum: IaaS, PaaS, and Serverless

Cloud architectures offer varying levels of abstraction:

  • IaaS (Infrastructure as a Service): Raw VMs (EC2, Compute Engine). Maximum control, but you are responsible for OS updates, security patches, and kernel tuning.
  • PaaS (Platform as a Service): Heroku, Render, Fly.io. You provide source code or a container; the platform manages routing, OS updates, and scaling.
  • Serverless (FaaS): AWS Lambda, Cloudflare Workers. Event-driven execution of individual functions billed strictly by memory and millisecond execution time.

5. Virtual Private Clouds (VPCs) & Routing

A Virtual Private Cloud (VPC) is your isolated virtual network. Best practice mandates dividing VPCs into:

  • Public Subnets: Host Internet Gateways and Load Balancers accessible from the public internet.
  • Private Subnets: Host application servers and database clusters with zero direct public IP addresses, routing outbound traffic through a NAT Gateway for security.

6. Regions & Availability Zones

A Region is a distinct geographic area (e.g., us-east-1 in Northern Virginia or eu-central-1 in Frankfurt).

Each region contains multiple Availability Zones (AZs). An AZ is one or more discrete datacenters equipped with independent power substations, cooling generators, and physical security, linked to neighboring AZs via ultra-low-latency private fiber. Designing a system to span at least two AZs protects against physical datacenter fires or localized power grid blackouts.

7. Scalability vs Elasticity

Scalability is the capability of a system to handle increased load by adding resources (Vertical scaling by adding CPU/RAM to a box, or Horizontal scaling by adding more boxes).

Elasticity is the degree to which a system can automatically adapt its capacity in real-time in response to dynamic load changes—spinning up 50 nodes during a Black Friday flash sale and automatically destroying them at midnight to prevent unnecessary compute bills.

8. The Shared Responsibility Security Model

Cloud security is a strict shared contract:

  • Provider Responsibility ("Security OF the Cloud"): Physical datacenter security, hypervisor patching, server firmware, and network hardware.
  • Customer Responsibility ("Security IN the Cloud"): Customer data, firewall rules (Security Groups), operating system patches on VMs, IAM permissions, and application code.

9. Frequently Asked Questions

Why can cloud bills unexpectedly skyrocket?

Compute instances are cheap, but egress bandwidth (data leaving the cloud provider to the internet) and unmonitored serverless invocation loops can generate tens of thousands of dollars in surprise charges. Always configure billing alerts and budget quotas on day one.

What is "Vendor Lock-in"?

Vendor lock-in occurs when an architecture relies heavily on proprietary cloud services (like DynamoDB or Cloud Spanner) that cannot be easily migrated to another cloud provider or self-hosted hardware without a complete application rewrite.
